## Known Issues

### 1. No Segment-Level Annotations Exist

**Severity:** CRITICAL — BLOCKING

No public dataset provides segment-level (utterance-level) labels for social-engineering tactics. All existing datasets use either:
- Binary labels (scam/non-scam) at the conversation level
- Multi-class labels (scam type) at the conversation level
- HMM-derived stage labels (conversation-level, not segment-level)

LUMINA requires segment-level multi-label annotations where each utterance can be labeled with multiple tactics simultaneously.

### 2. Scam Baiting ≠ Real Victim Behavior

**Severity:** HIGH

The largest available transcript datasets (Wood et al., BYU-PCCL, YouTube transcripts) are sourced from scam baiting videos. In scam baiting:
- The "victim" is a professional scam-baiter
- They deliberately deceive the scammer
- Their resistance, compliance, and responses are performative
- This does NOT represent genuine victim behavior

For LUMINA's USER_RESISTANCE label, scam-baiting data would train the model to recognize deliberate deception, not genuine victim pushback.

### 3. No Production-Use License

**Severity:** HIGH

The only large dataset (Composite Scam, 46,982 transcripts) is CC BY-NC, which prohibits commercial use. LUMINA is intended as a production system, so this dataset cannot be used without explicit permission.

### 4. Simulated Data Dominates

**Severity:** MEDIUM

Derakhshan's dataset (215 calls) was generated by volunteers simulating scam scenarios. Simulated data may not capture:
- Genuine emotional responses
- Natural conversation flow
- Real-world tactic evolution
- Diverse victim demographics

## Recommendations

### Immediate (This Phase)

1. **Do NOT train DeBERTa** — insufficient data
2. **Keep deterministic baseline** as the sole classification authority
3. **Document the blocker** clearly (done in this report)
4. **Maintain the prepared pipeline** for future use

### Medium-Term (Next Phase)

1. **Design an annotation protocol** for segment-level multi-label tactic classification
2. **Recruit expert annotators** with domain knowledge in social engineering
3. **Collect real phone call transcripts** with appropriate consent and licensing
4. **Establish inter-annotator agreement** metrics (target: Cohen's kappa > 0.7)

### Long-Term (Future)

1. **Create a custom annotated dataset** meeting LUMINA's requirements
2. **Validate annotation quality** with pilot studies
3. **Publish the annotation protocol** for reproducibility
4. **Train DeBERTa-v3** on the validated dataset

## Conclusion

**The dataset is too small for reliable deep-learning training.**

In fact, there is no dataset at all. The blocker is not dataset size or quality — it is the complete absence of segment-level multi-label annotated data for social-engineering tactics in phone conversations.

**The deterministic safety engine must remain the sole authority for LUMINA's safety function.**

ML cannot contribute meaningfully until a legitimate, sufficiently large, properly annotated dataset exists. The current deterministic baseline provides reliable, transparent, and auditable behavior.
