# LUMINA ML — Dataset Acceptance Criteria

**Document Version:** 1.0  
**Created:** 2026-09-07  
**Purpose:** Define acceptance criteria that a dataset must pass before training.  
**Status:** FINAL

---

## Overview

A dataset must pass ALL acceptance criteria below to be used for training. If ANY criterion fails, the dataset is REJECTED.

---

## Acceptance Criteria

### A1: Provenance Known

**Requirement:** Complete provenance chain from source to training example.

**Acceptance Test:**
- Every training example has a provenance record
- Source URL/location is documented
- Download date is recorded
- Verification status is confirmed

**Failure Condition:** Any training example lacks provenance.

**Evidence:** Provenance records in dataset manifest.

---

### A2: License Known

**Requirement:** Clear, verified license for every data source.

**Acceptance Test:**
- License text is available for every source
- License has been reviewed by legal team
- Commercial use is explicitly permitted
- Training use is explicitly permitted

**Failure Condition:** Any source has unknown or restrictive license.

**Evidence:** License records in dataset manifest.

---

### A3: Production Use Permitted

**Requirement:** License permits commercial/production use.

**Acceptance Test:**
- No CC BY-NC or similar non-commercial restrictions
- No research-only limitations
- No redistribution prohibitions (if needed)
- Legal team has confirmed production use is allowed

**Failure Condition:** Any source prohibits production use.

**Evidence:** Legal review document.

---

### A4: Consent Known

**Requirement:** Consent documented for all user-contributed data.

**Acceptance Test:**
- User-contributed data has explicit consent
- Consent covers training use
- Consent covers production use
- Consent can be withdrawn (mechanism in place)

**Failure Condition:** Any user-contributed data lacks consent.

**Evidence:** Consent records.

---

### A5: Not Synthetic

**Requirement:** No synthetic, LLM-generated, or fabricated data.

**Acceptance Test:**
- All data sourced from real conversations
- No data generated by language models
- No data augmented artificially
- No simulated scenarios presented as real

**Failure Condition:** Any synthetic data detected.

**Evidence:** Source verification, content analysis.

---

### A6: Labels Verifiable

**Requirement:** Annotations can be verified and traced.

**Acceptance Test:**
- Every annotation has an annotator ID
- Every annotation has a rationale
- Inter-annotator agreement measured
- Adjudication completed for disagreements

**Failure Condition:** Any annotation lacks traceability.

**Evidence:** Annotation records, agreement metrics.

---

### A7: PII Safely Removed

**Requirement:** All PII and secrets detected and redacted.

**Acceptance Test:**
- PII detection applied
- Phone numbers redacted
- Email addresses redacted
- SSN/ID numbers redacted
- Passwords/OTP redacted
- Spot-check confirms no PII remains

**Failure Condition:** Any PII detected in training data.

**Evidence:** PII filter logs, spot-check report.

---

### A8: No Data Leakage

**Requirement:** No information leakage between splits.

**Acceptance Test:**
- No conversation appears in multiple splits
- No near-duplicate text across splits
- No source overlap between splits
- Deduplication applied within splits

**Failure Condition:** Any leakage detected.

**Evidence:** Leakage detection report.

---

### A9: No Duplicate Conversations Cross Splits

**Requirement:** Conversation-level splitting with no overlap.

**Acceptance Test:**
- All segments from one conversation in same split
- No conversation ID appears in multiple splits
- Split manifest confirms no overlap

**Failure Condition:** Any conversation spans multiple splits.

**Evidence:** Split manifest, overlap check.

---

### A10: Train/Test Contamination Free

**Requirement:** No test data influences training.

**Acceptance Test:**
- Test set is held out before any training
- No test data used for hyperparameter tuning
- No test data used for model selection
- Test set remains untouched until final evaluation

**Failure Condition:** Any test data contamination detected.

**Evidence:** Training logs, experiment records.

---

## Acceptance Process

### Step 1: Self-Assessment

Dataset creator runs all acceptance tests and documents results.

### Step 2: Peer Review

Another team member reviews the acceptance test results.

### Step 3: Legal Review

Legal team confirms license and consent compliance.

### Step 4: Quality Review

Quality team confirms annotation quality and PII removal.

### Step 5: Final Decision

- If ALL criteria pass → Dataset ACCEPTED
- If ANY criterion fails → Dataset REJECTED

### Step 6: Documentation

Document the acceptance decision with evidence.

---

## Rejection Handling

If a dataset is rejected:

1. Document the specific failure criteria
2. Identify remediation steps
3. Estimate time/cost to fix
4. Decide whether to remediate or abandon
5. If remediated, re-run acceptance process
